知学AI — 业务流程分析文档

一、项目概述

知学AI 是一个面向 AI 与编程教育的在线学习平台，提供课程浏览、购买、学习、AI 智能辅助等完整功能。平台采用 B2C 模式，支持学生、教师、管理员三种角色。

核心业务流：用户注册 → 浏览课程 → 购买/秒杀 → 学习课程 → AI 辅助 → 完成学业


二、总体业务流程图（文字描述）

前端访问层：用户访问网站 -> 已注册？是->登录系统，否->注册账号 -> 登录系统
课程浏览：课程列表 -> 搜索/筛选课程 -> 查看课程详情 -> 免费课程？是->直接加入学习，否->加入购物车/秒杀/购买
交易支付：下单 -> 支付宝支付/模拟支付 -> 支付成功 -> 开通课程权限
学习中心：我的课程 -> 视频学习 -> 做笔记 -> AI 提问 -> 作业练习 -> AI 批改
教师管理：创建课程 -> 上传章节/课时 -> 上传知识库 -> 提交审核 -> 管理员审核 -> 课程上架

流程连接：登录后->课程浏览，直接加入学习->学习中心，开通课程权限->学习中心，购买->下单


三、子模块详细流程图

3.1 用户认证模块

用户访问 -> 选择登录方式

密码登录分支：输入账号/密码 -> 服务端验证 -> 验证通过？是->签发 JWT Token，否->返回错误提示 -> 重新输入

验证码登录分支：输入手机号 -> 点击获取验证码 -> 60s 冷却检查 -> 允许发送？否->提示"请60秒后再试"，是->生成4位随机码 -> 是否启用真实短信？是->通过容联云发送短信，否->Mock模式返回验证码到前端 -> 存入 Redis 5分钟有效 -> 用户输入验证码 -> Redis 比对验证码 -> 匹配？是->签发 JWT Token，否->验证码错误

注册分支：填写用户名/手机/邮箱/密码 -> 获取验证码 -> 提交注册 -> 手机或邮箱已注册？是->409 冲突，否->创建用户 -> 自动登录，跳转首页

Token 处理：签发的 JWT -> Redis 记录 Token 白名单 -> 返回 access_token -> 前端存入 localStorage -> 跳转首页

技术要点：
- JWT Token 签发时记录 jti 到 Redis，用于登出/踢下线
- get_current_user_optional 支持未登录用户的匿名访问
- 密码使用 bcrypt（passlib）哈希存储
- 验证码使用 Redis 存储，60s 冷却 + 300s 有效期


3.2 课程浏览与搜索模块

课程列表页：加载课程列表 -> 查询参数 -> 分类筛选 / 关键词搜索 / 排序:热度/价格/评分 / 分页加载

课程详情页：加载课程基本信息 -> 加载 SKU/价格 -> 加载课程章节大纲 -> 加载教师信息 -> 加载课程评价 -> 加载秒杀活动信息 -> 用户已登录？是->查询是否已购买，否->显示"立即购买" -> 已购买->显示"开始学习"，未购买->显示"立即购买"

秒杀专区：加载全部秒杀课程 -> 过滤已过期活动 -> 倒计时展示 -> 动态更新库存/进度条

全文搜索：用户输入关键词 -> 调用 ES 搜索 API -> 多字段匹配:标题/描述/分类 -> IK 中文分词 -> 高亮匹配片段 -> 返回排序结果

课程列表加载时判断 ES 是否启用，启用则走全文搜索，否则走传统查询。


3.3 购物车与下单模块

购物车：查看购物车 -> 购物车为空？是->显示空购物车，否->展示 SKU 列表 -> 修改数量 / 删除商品 / 清空购物车 -> 更新 Redis 哈希

下单流程：点击"去结算" -> 检查秒杀活动状态 -> 秒杀有效且库存充足？是->使用秒杀价，否->使用原价 -> 创建订单 -> 分布式锁防止重复下单 -> 扣减库存 MySQL 行锁 -> 库存足够？否->返回库存不足，是->创建订单记录 -> Redis 缓存订单号 -> 创建订单条目 OrderItem -> 返回订单号

关键实现：
- 购物车完全基于 Redis Hash 存储，每个用户一个 key
- 下单使用 Redis 分布式锁防止多次提交
- MySQL 行级锁（SELECT...FOR UPDATE）保证库存并发安全
- 订单支持秒杀价自动替换


3.4 支付模块

支付流程：用户请求支付 -> 支付模式？支付宝->调用支付宝 SDK 创建交易 -> 获取支付宝表单/二维码；模拟支付->生成模拟支付二维码；微信->返回模拟二维码(未接入) -> 展示支付页面 -> 用户扫码支付 -> 前端轮询订单状态 -> 每隔2s调用 /pay/status -> 订单已支付？是->跳转到学习页面，否->超时30分钟？是->订单自动取消，否->继续轮询

支付回调：支付宝异步通知 -> 验证签名 -> 签名有效？是->更新订单状态为 paid -> 清空购物车相关商品 -> 创建 UserCourse 记录 -> 返回 success 给支付宝

订单超时：后台定时任务每30s扫描 -> 查询超时未支付订单 -> 恢复库存 -> 取消订单


3.5 秒杀模块

秒杀准备：管理员创建秒杀活动 -> 管理员预热缓存 -> Redis 写入 seckill:stock:ID = 库存量

用户秒杀：用户点击"立即秒杀" -> 令牌桶限流检查 -> 限流通过？否->提示"人数过多"，是->用户级别限流:1次/s -> 通过？否->提示"操作太频繁"，是->Redis DECR 扣减库存 -> 库存>0？否->提示"已售罄"，是->订单信息推送到 Redis 队列 -> 返回排队 ID 给用户

异步处理：5个 Worker 监听队列 -> 从队列弹出订单 -> MySQL 行锁扣减 SKU 库存 -> 库存足够？否->标记失败:已售罄，是->创建订单 -> 标记成功并记录 SN -> 记录秒杀结果到 Redis

前端轮询：用户收到排队 ID -> 前端轮询 /seckill/result -> 等待 1-10s(指数退避) -> 已出结果？否->继续轮询，是->成功？是->跳转到支付页，否->显示失败原因

高性能设计：
- 令牌桶限流：系统级（100rps）+ 用户级（1rps）
- Redis DECR 是原子操作，保证不超卖
- 异步队列解耦：用户无需等待 MySQL 写入
- 前端轮询 + 指数退避（1s 到 1.5s 到 ... 到 10s）
- 崩溃恢复：Worker 启动时重新处理卡住的订单


3.6 学习模块

课程学习：进入我的课程 -> 选择课程 -> 加载课程大纲+章节列表 -> 选择章节/课时 -> 有观看权限？否->是否免费试看？是->播放视频并显示"试看"标记，否->提示"请购买课程"；是->播放完整视频

视频播放时同步进行：
记录学习进度到 MongoDB -> 更新课程最后学习时间
做笔记 -> 保存到 MongoDB
AI 提问 -> 调用 /ai/knowledge/chat 结合知识库回答
课程问答 -> 提问/查看回答

学习进度追踪：每30s更新进度 -> 写入 MongoDB -> lesson_progress 记录 lesson_id + user_id + watched_seconds + completed -> 课程进度汇总到 course_progress 记录总进度百分比


3.7 AI 功能模块

AI 对话：用户发送消息 -> 搜索所有课程知识库 -> ChromaDB 向量检索 Top-K -> 联网搜索补充实时信息 -> 加载最近20条聊天历史 -> 构建 System Prompt + Context -> 调用 LLM API SiliconFlow/Qwen -> 返回回答 -> 保存对话到 MongoDB

AI 推荐：用户输入学习需求 -> LangGraph 解析意图 -> 搜索知识库获取上下文 -> LLM 匹配课程 -> 返回推荐列表 -> 推荐为空？是->返回热门课程兜底

AI 出题：选择课程+章节 -> 指定知识点/难度 -> LangGraph 多Agent工作流 -> 检索知识库参考内容 -> LLM 生成题目 -> 格式化输出:题目+选项+答案

AI 批改：学生提交答案 -> LangGraph 检索参考知识点 -> LLM 评分+评语 -> 返回分数+评语


3.8 教师管理模块

课程管理：讲师登录 -> 进入讲师后台 -> 已有课程？否->创建新课程，是->编辑已有课程 -> 填写课程信息:标题/分类/价格/封面 -> 创建章节 -> 创建课时:视频/时长 -> 上传知识库文档 -> 提交审核

知识库管理：上传文件 -> 文件类型？TXT->直接读取内容；PDF->PyPDFLoader 提取；DOCX->docx2txt 提取 -> 文本分块 Chunk -> 计算 Embedding 向量 -> 存入 ChromaDB -> 记录向量索引元数据

秒杀管理：查看 SKU 列表 -> 创建秒杀活动 -> 设置秒杀价/库存/时间 -> 提交管理员审核

销售统计：查看销售看板 -> 总销售额/订单数 -> 热销课程排行 -> ECharts 图表展示


3.9 管理员模块

管理员仪表盘：登录管理员账号 -> 查看系统仪表盘 -> 总用户数/课程数/订单数 -> 待审核事项汇总

用户管理：用户列表 -> 查看用户详情 -> 启用/封禁用户 -> 删除用户(硬删除)

审核管理：
待审核课程 -> 查看课程详情 -> 通过/拒绝
待审核讲师 -> 查看讲师申请 -> 通过/拒绝
待审核秒杀 -> 查看秒杀活动 -> 通过/拒绝

订单管理：订单列表 -> 按状态筛选 -> 查看订单详情 -> 退款处理

五、数据流转图（文字描述）

MySQL 存储：users、courses、course_skus、orders、order_items、chapters、lessons、seckill_activities、user_courses
Redis 存储：JWT Token、购物车、秒杀库存、验证码、用户限流
MongoDB 存储：学习进度、笔记、聊天历史
Elasticsearch 存储：课程索引
ChromaDB 存储：知识库向量
文件存储：视频文件、课程封面、知识库文档

数据流向：
users -> JWT Token (从 MySQL 到 Redis)
course_skus -> 秒杀库存 (从 MySQL 到 Redis)
users -> 购物车 (从 MySQL 到 Redis)
users -> 用户限流 (从 MySQL 到 Redis)
lessons -> 学习进度 (从 MySQL 到 MongoDB)
users -> 聊天历史 (从 MySQL 到 MongoDB)
courses -> 课程索引 (从 MySQL 到 Elasticsearch)
chapters -> 知识库向量 (从 MySQL 到 ChromaDB)
lessons -> 视频文件 (从 MySQL 到文件存储)
courses -> 课程封面 (从 MySQL 到文件存储)


六、总结

知学AI 平台是一个功能完整的在线教育系统，覆盖了从用户注册、课程浏览/搜索、购物车/秒杀交易、支付、学习到管理后台的全链路业务流程。系统采用微服务化设计思想，不同数据存储承载不同职责：

MySQL：核心业务数据（用户、课程、订单）
Redis：高并发场景（秒杀、限流、缓存、Token）
MongoDB：用户行为数据（进度、笔记、聊天）
Elasticsearch：全文搜索
ChromaDB：AI 知识库向量存储

这种混合存储架构充分利用了各类数据库的优势，在高并发秒杀场景下做到了不超卖、高性能。
